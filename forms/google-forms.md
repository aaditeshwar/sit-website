# Google Forms for regular updates

Five forms feed the site's frequently changing content. Each form writes to its own response sheet. A moderator sets the same visibility value the CSV stores, and the import copies that value into the files under `data/`.

The import does not use a Google Cloud account. Publish each response sheet to the web and paste that link in `forms/published-sheets.env`. Optional questions may be left off the form. The title (for alumni, the full name) is the match key. A different title is a new item; the previous row stays until its own sheet row hides it. A blank visibility cell updates the other fields of an existing row and leaves it shown or hidden as it already was. A new title with a blank or hidden value is not added. A blank cell keeps the current value. A cell containing only `-` clears that value. A file-upload image is downloaded when that Drive file is shared as anyone with the link. The same image question also has a URL field. A site path such as `/images/research/photo.png` keeps the file already in the repository. A blank image cell keeps the current file. A link that points at a page on this site is stored as a path, such as `/academics/research-fellows`. Dropdown answers are the same tokens the CSV stores. Older labels, such as `Announcement` or `Call for proposals`, still match.

**Rules for every form**
- Leave respondent email **off**. The published sheet is world-readable, so an email column would be public.
- Each Sheet tab gets moderator columns added to the right of the form responses: `edited_*` overrides (optional, see below) and `moderator_note`. News, events, and alumni also have `status` (`published` or `draft`). Openings use `status` (`open`, `closed`, or `draft`). Projects use `moderation` (`TRUE` or `FALSE`), because `status` is already the project's own state.
- `published`, `open`, and `TRUE` show the row. `draft` and `FALSE` keep an existing row and hide it. `closed` keeps an opening in the list and marks it closed. A blank cell does not change whether the row is shown.
- If a moderator needs to fix a field, they type the corrected value in a column named `edited_<column>`. The import prefers `edited_x` over `x`, so original submissions are never overwritten.
- Images: use a **file-upload question** and share each file as anyone with the link, **or** an image URL anyone can open. Max 10 MB, image types only.

## 1. News item → `data/news.csv`

| # | Question (as shown in the form) | Type | Required | CSV column | Notes |
|---|---|---|---|---|---|
| 1 | Headline | Short answer (≤ 120 chars) | yes | `title` | |
| 2 | Date of the news | Date | yes | `date` | ISO `YYYY-MM-DD` |
| 3 | Category | Dropdown: Achievement / Announcement / Event / Opportunity / Media coverage / Admissions notice | yes | `category` | lower-case slug: `achievement`, `announcement`, `event`, `opportunity`, `media`, `admissions-notice` |
| 4 | One-paragraph summary (shown on cards) | Paragraph (≤ 400 chars) | yes | `summary` | |
| 5 | Full text (optional; markdown allowed) | Paragraph | no | `body_md` | If present, a detail page `/news/<id>` is generated |
| 6 | Link for more information | Short answer (URL) | no | `link` | |
| 7 | Image | File upload (1 file) | no | `image` | The sheet also has Image (URL). Use one of the two. A path `/images/...` keeps the local file. An upload is saved to `assets/images/news/<id>.<ext>` |
| 8 | Image credit / alt text | Short answer | if image | `image_alt` | |
| 9 | Thrust area (if any) | Checkboxes: the four thrust areas | no | `thrust_area` | `;`-separated slugs |
| 10 | Faculty / students involved | Short answer | no | `people` | `;`-separated names, matched against `data/people/*.csv` |
| — | (respondent email) | auto | — | `submitted_by` | |
| — | (moderator) | — | — | `status`, `featured` | `featured=TRUE` puts it in the home-page hero row |

`id` is generated by the import: `slugify(title)` trimmed at a word boundary (≤ 60 chars), made unique with a `-2` suffix.

## 2. Project → `data/projects.csv`

| # | Question | Type | Required | CSV column | Notes |
|---|---|---|---|---|---|
| 1 | Project title | Short answer | yes | `title` | |
| 2 | Is this an update to an existing project? If so, paste its current title or page link | Short answer | no | `update_of` | import overwrites the matching `id` |
| 3 | Thrust area | Multiple choice: the four thrust areas | yes | `thrust_area` | |
| 4 | Stage | Multiple choice: **Project** (focused work with a line of sight to deployment) / **Initiative** (several co-owners, products/platforms, external funding) / **Ecosystem** (integrated with government / civil society / industry at scale) | yes | `stage` | `project` / `initiative` / `ecosystem` |
| 5 | Status | Multiple choice: Ongoing / Open for students / Proposed — seeking collaborators or funding / Completed | yes | `status` | `ongoing` / `open-for-students` / `proposed` / `completed` |
| 6 | One-to-two-sentence summary | Paragraph (≤ 300 chars) | yes | `summary` | |
| 7 | Detailed description (markdown allowed) | Paragraph | no | `description_md` | generates `/research/projects/<id>` |
| 8 | Lead and co-faculty | Short answer | yes | `faculty` | `;`-separated IITD email ids (the part before `@`, such as `aseth`). A full address or the person's name also matches. The import stores the email id. The site shows the name from `faculty.csv` |
| 9 | Partners / collaborators | Short answer | no | `partners` | `;`-separated |
| 10 | Sponsor / funding programme | Short answer | no | `sponsor` | e.g. "R-Systems CoE for Applied AI for Sustainable Systems" — exact text links the project to the CoE page |
| 11 | Who are you looking for? | Checkboxes: PhD / MS (Research) / Pre-doc (Research Fellow) / Research assistant / Post-doc / Software engineer / Collaborators / Funding | no | `seeking` | `;`-separated: `PhD;MSR;Predoc;RA;Postdoc;Software engineer;Collaborators;Funding` |
| 12 | Background expected from applicants | Paragraph | no | `background` | |
| 13 | Website | Short answer (URL) | no | `website` | |
| 14 | Image (landscape, ≥ 1200 px wide) | File upload | no | `image` | The sheet also has an Image URL column. Use one of the two. A path `/images/...` keeps the local file |
| 15 | Start year | Short answer (YYYY) | no | `start_year` | |
| 16 | Linked to an ongoing initiative | Dropdown: CoRE stack / Gram Vaani / Assistech / Computer architecture / Cybersecurity | no | `initiative` | `core-stack;gram-vaani;assistech;computer-architecture;cybersecurity` |
| — | (moderator) | — | — | `status` (moderation), `featured`, `published` | moderation status lives in the Sheet column `moderation`, to avoid clashing with the project's own `status` |

**Note:** for the projects tab the moderator column is called **`moderation`** (`TRUE` shows the project, `FALSE` hides it), because `status` is already a project field. The import writes that value into the CSV column `published`.

## 3. Event → `data/events.csv`

| # | Question | Type | Required | CSV column |
|---|---|---|---|---|
| 1 | Event title | Short answer | yes | `title` |
| 2 | Type | Dropdown: Workshop / Talk / Conference / Viva / Outreach / Other | yes | `type` |
| 3 | Start date | Date | yes | `start_date` |
| 4 | End date | Date | no | `end_date` |
| 5 | Venue | Short answer | yes | `venue` |
| 6 | Summary | Paragraph | yes | `summary` |
| 7 | Registration / details link | URL | no | `registration_url` |
| 8 | Poster or image | File upload | no | `image` | Sheet headers `Image (upload)` and `Image (URL)`. Use one of the two. A path `/images/...` keeps the local file |

A sheet header `Link` is read as the registration / details link. A sheet header `Image` is read as the poster. The moderator column is `status`: `published` or `draft`. `draft` is left out of the public site.

## 4. Opening → `data/openings.csv`

| # | Question | Type | Required | CSV column |
|---|---|---|---|---|
| 1 | Position / call title | Short answer | yes | `title` |
| 2 | Type | Dropdown: Fellowship / Position / Internship / Call for proposals | yes | `type` |
| 3 | Summary | Paragraph | yes | `summary` |
| 4 | Link to apply or advertisement | URL | yes | `apply_url` |
| 5 | Deadline | Date (or leave blank for rolling) | no | `deadline` |

The moderator column is `status`: `open`, `closed`, or `draft`. Those values are stored unchanged. The build also shows an `open` row as **closed** once its `deadline` has passed. `draft` is left out of the public site. A sheet header `Application link` is read as the apply link.

## 5. Alumni update → `data/people/alumni.csv`

| # | Question | Type | Required | CSV column |
|---|---|---|---|---|
| 1 | Full name (as at graduation) | Short answer | yes | `name` (matching key) |
| 2 | Programme | Multiple choice: PhD / MS (Research) / M.Tech. | yes | `programme` |
| 3 | Graduation year | Short answer | yes | `graduation_year` |
| 4 | Thesis title | Short answer | no | `thesis_title` |
| 5 | Supervisor(s) | Short answer | no | `supervisor` |
| 6 | Current position and organisation | Short answer | no | `current_position` |
| 7 | Profile link (LinkedIn, homepage) | URL | no | `profile_url` |
| 8 | Photo | File upload | no | `photo` | Sheet headers `Photo (upload)` and `Photo (URL)`. Use one of the two. A path `/images/...` keeps the local file |
| 9 | A short story: what you work on now and how SIT shaped it (≤ 150 words) | Paragraph | no | `story_md` |
| 10 | I consent to this information being published on the SIT website | Checkbox | yes | `consent` (rows without consent are skipped) |
| — | (moderator) | — | — | `status` |

`draft` stays in the CSV and is left off the public site. A blank `status` on a row already in the directory still shows. `Current position and organization` is read as the organisation field.

## Optional 6. Faculty / student profile update

Same pattern for `faculty.csv` (research interests, thrust areas, profile URL, photo) and `students.csv` (supervisor, interests, photo, year joined). Matching key: `name` + respondent email.
